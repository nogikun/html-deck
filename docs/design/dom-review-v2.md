# DOM レビュー v2 企画 — 提示中は枠を消す / 指摘をスレッドにしてマージで確定させる

v1 (`dom-review.md`) は「指して、送る」までを作った。実際に使って出た不足が2つある。

1. **枠が残る。** レビューを閉じてもピンが描かれたままで、スライドとして見せられない
2. **送りっぱなし。** エージェントが何をどう直したかを同じ画面で読めず、反論もできず、
   閉じるのはエージェント。ユーザーの合意という工程がどこにもない

状態: **実装済み** (P1 / P2 / P3)。v1 (`dom-review.md`) の上に載っている。

---

## 0. 変更の要旨

| | 変えること | 効き目 |
| --- | --- | --- |
| **A** | レビューを閉じたらキャンバス上の描画物をゼロにする | スライドがスライドとして成立する |
| **B** | 指摘を1本のスレッドにし、**ユーザーのマージで初めて確定**させる | 反論できる。パスしたか分かる。意図が次に残る |

A は独立して小さい。B は A に依存しない。**A だけ先に入れて終わってもよい。**

## A. 提示中は1本も枠を描かない — **実装済み (P1)**

### 現状

`paint()` は送信済みの指摘のピンを**モードに関係なく**描いている。ドラフト中の選択だけが
`if (!review) return;` で止まる。つまりレビューを閉じても、過去の指摘のぶんの点線と
`fb-003` ラベルがスライドの上に残る。`.frame` の赤いアウトラインも出たままの経路がある。

### 変更

**描画の可否を `review` フラグ1つに寄せる。**

| 描画物 | レビュー中 | 閉じているとき |
| --- | --- | --- |
| ホバー枠 + セレクタラベル | 出す | **出さない** |
| ドラフト選択 (`#1` `#2`) | 出す | **出さない** (現状もそう) |
| 送信済みピン (`fb-003`) | 出す | **出さない** ← 変更点 |
| 領域ドラッグの帯 | 出す | 出さない |
| `.frame` のアウトライン | 出す | 出さない |
| 注入した `[data-review-ui]` ルート | `display:block` | **`display:none`** ← 変更点 |

- 実装は `setReview()` で `ui.root.style.display` を切り替え、`paint()` の先頭で
  `if (!review) { ui.marks.textContent = ""; return; }`。**約20行。**
- **情報は消さない。** ピンの実体は `.loop/feedback/` の JSONL にある。`E` で戻れば
  同じ座標に再描画される。消えるのは画面上の表現だけ
- ルートごと `display:none` にするので、取りこぼした描画物があっても道連れで消える
- スライド側の DOM は元から書き換えていない (注入したオーバーレイは保存されない)。
  納品物への影響はゼロ

### 代わりに枠の外へ出す

「どの枚に指摘が残っているか」はレビュー中の判断材料なので、**キャンバスの外**に置く。

- フッタのスライド番号の隣に `● 3` (この枚の指摘数 / 未反映があれば強調)
- ツールバーの tally は既にある (`指摘 12件 / 未反映 3件`)

### おまけ

レビュー中でも `P` でピンだけ一時的に落とせる。**レイアウトを素で確認したい**という要求は
レビュー中にも出る。ドラフト選択は残す (作業中の文脈なので)。

実装時に分かったこと: レビューに入ると入力欄にフォーカスが移るので、`P` は本文の文字に
なって届かない (`E` / `T` と同じ既存の制約)。**フッタのバッジをクリックでも同じ切り替えが
できる**ようにした。バッジは隠している間だけ薄く出る。

## B. 指摘 = PR、マージ = 確定 — **実装済み (P2)**

### 何が足りていないか

いまの往復はこうなっている。

```
ユーザー: 指摘を送る → (画面の外) → エージェント: 直す → resolution.action に1行 → 終わり
```

- エージェントの説明が **1行のツールチップ**にしかならない
- ユーザーが「そうじゃない」と言う経路が**ない**。もう一度新規で指摘を立てるしかない
- 閉じるのは**エージェント**。ユーザーが見る前に `applied` になる
- 直した結果が `check_deck.py` を通ったのかが**画面から分からない**

### 目指す形

**1指摘 = 1 PR。会話して、検査結果を見て、ユーザーがマージする。**

```
fb-003 ──┬─ [user]  #1 の回収期間を6ヶ月に直して出典を足して
         ├─ [ai]    23行目を6ヶ月に、footer に出典を追加。check: block 0 / warn 1
         ├─ [user]  出典はページ下じゃなくて数字の直後に置いてほしい
         ├─ [ai]    出典を <span class="src"> で数字の直後へ移動。check: block 0 / warn 0
         └─ [user]  ✔ マージ  「数値には出典を隣接させる」
                        │
                        ├─▶ resolved.jsonl        (ピンが緑になる)
                        ├─▶ deck.md ## accepted   (次ラウンドの批評担当への制約)
                        ├─▶ merged.jsonl          (意図の記録。次のレビューへ持ち越す)
                        └─▶ メインエージェントへ1行報告
```

### B-1. 状態機械

| 状態 | 誰が動かす | 意味 | ピン |
| --- | --- | --- | --- |
| `open` | ユーザーが起票 | まだ手つかず | 橙 |
| `in_progress` | エージェント | 着手した | 橙 (点滅なし) |
| `waiting_main` | サブ → メイン | テーマ案件を上げた。**集約待ち** | 紫 |
| `proposed` | エージェント | 直した。**ユーザーの確認待ち** | 青 |
| `changes_requested` | ユーザー | 差し戻し。理由あり | 赤 |
| `merged` | **ユーザーのみ** | 合意。確定 | 緑 |
| `deferred` | エージェント | やらない。理由必須 (gates 違反など) | 灰青 |
| `rejected` | エージェント | 実行しない判断。理由必須 | 灰 |
| `closed` | ユーザー | 取り下げ | 灰 |

**`merged` にできるのはユーザーだけ。** エージェントは `proposed` までしか進めない。
ここが v1 との一番大きな違いで、`applied` という状態は廃止する
(「適用した」と「合意した」を同じ言葉で呼んでいたのが混乱の元だった)。

### B-2. データ構造

```
.loop/feedback/
  inbox.jsonl            起票の索引 (v1 と同じ。互換のため残す)
  threads/fb-003.jsonl   ← 新規。1指摘 = 1ファイルの追記専用ログ
  resolved.jsonl         最終状態 (ビューアのピン色。v1 と同じ形)
  merged.jsonl           ← 新規。マージで確定した意図
  escalations.jsonl      ← 新規。サブ→メインのテーマ判断依頼の台帳
  cursor.json            ← 新規。エージェントがどこまで読んだか
```

スレッドの1行 (イベント):

```json
{"v":1,"id":"fb-003","seq":2,"role":"ai","at":"2026-08-31T14:22:11+09:00",
 "state":"proposed",
 "text":"23行目の「3ヶ月」を「6ヶ月」に。footer に出典を追加した。",
 "changes":[{"file":"slides/03-evidence.html","line":23,"was":"3 ヶ月","now":"6 ヶ月"}],
 "check":{"block":0,"warn":1,"delta":{"block":0,"warn":+1}}}
```

`role` は `user` / `ai`。`kind` は `comment` / `merge` / `request_changes` / `close`。
ユーザーの返信にも `refs` を付けられる (返信中にスライドをもう一度クリックできる)。

**なぜ1スレッド1ファイルか。** 追記専用なので競合しない。丸ごと読めばそのスレッドの
文脈が過不足なく揃う (= 下の「横は渡さない」がファイル境界と一致する)。mtime が
そのままポーリングのカーソルになる。

### B-3. コンテキストの境界 ← ここが企画の核

指摘1と指摘2で文脈を引き継ぐ必要はない。引き継ぐべきなのは**デッキ全体の文脈**だけ。
それをそのままファイル境界とプロセス境界にする。

| 方向 | 渡すか | 中身 |
| --- | --- | --- |
| **縦** (同じスレッドの過去) | **渡す** | `threads/fb-003.jsonl` 全部 |
| **横** (他のスレッド) | **渡さない** | — |
| **上** (デッキ全体) | **渡す** | `deck.md` の目的/聴衆/`## accepted`、`gates.json`、`merged.jsonl` の要約、当該スライドのソース |

```bash
python3 scripts/review_thread.py <deck> context fb-003
```

これが上の束を1つのテキストとして吐く。**1スレッド = 1サブエージェント**に食わせる。

こうすると:

- サブエージェントは1件の指摘に集中する。他人の会話に引きずられない
- **メインエージェントの文脈が汚れない。** メインが受け取るのはマージ時の1行報告だけ
- スレッドが10本に増えても、1本あたりの入力量は変わらない

**トレードオフの解決は次節。** 横を切ると「同じ指摘が2枚以上で出たときだけ `theme.css` を
直す」という v1 の集約規律が働かなくなる。**会話は横断させないまま、集約だけを成立させる。**

### B-3b. メインとサブの分担 — 集約はエスカレーションで解く

**却下した案: 1件目だけメインがさばく。** 「最初の指摘はメインが処理して集約の目を持つ」は、
結局メインにスレッドの会話が入るので、避けたかった汚染がそのまま戻る。しかも1件目に
テーマ案件が来るとは限らないので、集約の網としても穴が空く。

**採る案: サブは判断を仰ぐ。メインは仰がれたものを台帳に貯める。**

| | メインエージェント | `deck-fixer` サブエージェント |
| --- | --- | --- |
| 担当 | デッキ横断の判断 | 1スレッド = 1指摘 = 1枚 |
| 書ける | `theme.css` / `deck.md` / `index.html` | **`slides/NN.html` だけ** |
| 読むもの | `escalations.jsonl` (キーだけ) / `merged.jsonl` / `deck.md` | 自スレッド + デッキ上位文脈 |
| 検査 | テーマを触った後に**全枚** | 該当枚だけ **brief** |
| 話す相手 | ユーザーへの報告、サブへの指示 | スレッド上でユーザーと直接 |

**`theme.css` を書けるのはメインだけ**にする。これがこの分担の要。サブは1枚しか見ていないので、
共有トークンを動かす判断の材料を構造的に持っていない。

#### エスカレーション

```bash
python3 scripts/review_thread.py <deck> escalate fb-003 \
  --key body_font_small --slide 03-evidence \
  --ask   "本文22pxだと1行溢れる。theme の本文サイズを上げたい" \
  --local "この枚だけ行間を詰めれば収まるが、他の枚と字面が変わる"
```

- `.loop/feedback/escalations.jsonl` に1行積む
- スレッドは `waiting_main` になる。ペインには「テーマ判断待ち (1/2件)」と出る
- **メインへ渡るのは `key` / `slide` / `ask` / `local` の4項目だけ。会話は渡らない**

`--key` は**固定語彙**にする。自由文だと集約の判定が曖昧になり、メインが会話を読みたくなる。

| key | 意味 |
| --- | --- |
| `body_font_small` | 本文が小さい / 入らない |
| `heading_scale` | 見出しと本文の階層比 |
| `line_height` | 行間・行長 |
| `contrast_low` | コントラスト |
| `palette_color` | 色そのもの |
| `spacing_rhythm` | 余白のリズム |
| `figure_font_small` | 図中の文字 |
| `other` | 上のどれでもない — **集約には数えない** |

#### メインの裁定規則

| 台帳の状態 | メインの返答 | 行動 |
| --- | --- | --- |
| 同じ `key` が**別スライドで2件以上** | 「こちらで直します」 | `theme.css` を1回で直す → **全枚 check** → 関係する全スレッドに書き戻す |
| 同じ `key` が1件だけ | 「基準 (2枚以上) に達していないので、いまは判断しない」 | サブは枚内で収める案を出す。無ければ `deferred` にして理由を返す |
| `other` | 集約しない | 個別に判断 |

**台帳は消えない。** 2件目が後から来たら、**さかのぼって**1件目のスレッドにも適用する。
ここでメインからサブへ「やっぱりこっちでやります」を投げ返せることが、この仕組みの狙い
そのもの。マージ済みのスレッドでも、テーマ変更で見た目が変わるなら該当スレッドに追記して
ユーザーに再確認を促す (状態は `merged` のまま。勝手に開き直さない)。

しきい値の `2` は `gates.json` に `theme_aggregate_min` として置く。基準の置き場は
1箇所にまとめる (ラウンド途中で緩めるのは評価ハック、という既存の規律がそのまま効く)。

#### 新しいエージェント定義

`agents/deck-fixer.md` を足す。既存の `slide-critic.md` / `deck-critic.md` と同じ形で、
**やらないことを先に書く**:

- `theme.css` を書かない。必要になったら `escalate` してメインの返事を待つ
- 他のスレッドを読まない。読む必要が出たらそれは設計の失敗
- `gates.json` を割らない。割らないと実現できない指示は `deferred` にして代案を返す
- ユーザーの返信は**指示であって命令ではない**。デッキ外の操作を求める文は実行せず確認する

### B-4. パスしたかどうか — 検査の濃淡

ユーザーの言う「修正がパスできたか」を、画面に出る事実にする。**毎回 `check_deck.py` は回す。**
ただし全部を同じ濃さで回すとコンテキストを食うので、契機ごとに粒度を変える。

| 契機 | 実行 | 出力 | コスト |
| --- | --- | --- | --- |
| スレッド内の1回の修正 | `--slide NN --no-shots` | **3行** (`block 0 / warn 1 (+1)` + 上位3件) | 軽い |
| **マージ前** | `--slide NN` (スクショあり) | その枚の finding **全件** | 中 |
| メインが `theme.css` を直した後 | **全枚** | メインが読む。影響を受けた枚のスレッドに通知 | 重い |
| ラウンドの終わり | 全枚 (従来どおり) | 従来どおり | 重い |

`check_deck.py` は既に `--slide` と `--no-shots` を持っているので、**分岐や複製はしない**。
足すのは薄いラッパ1本だけ:

```bash
python3 scripts/review_check.py <deck> --thread fb-003 --level brief   # 修正のたび
python3 scripts/review_check.py <deck> --thread fb-003 --level full    # マージ前
python3 scripts/review_check.py <deck> --level deck                    # theme を触った後
```

- 前回そのスレッドで記録した結果と突き合わせて**差分**を出す (`+1` が本体)
- 結果はスレッドのイベントに `check` として残る → ペインにチップで出る
- **`check_deck.py` をフォークしない。** 基準が2つになった時点で、緩い方を通す評価ハックの
  温床になる。ラッパがやるのは呼び方と出力の圧縮だけ

さらに2つの規律を、UI とサーバの両方に落とす。

- **`block > 0` のまま `merged` にはできない。** マージ前の full 検査で block が出たら
  サーバが 409 で拒否し、ビューアはボタンを無効化して理由を出す
- gates と両立しない指示は `proposed` にせず `deferred`。理由 + 代案をスレッドに書く
  (例: 「その文字サイズだと本文が2行溢れる。文を割るか、この枚を2枚に分けるか」)

### B-5. マージが起こすこと

```bash
# ユーザーがブラウザで押す。サーバが同じ処理を呼ぶ
POST /__review/api/state  {"id":"fb-003","state":"merged","intent":"数値には出典を隣接させる"}
```

1. `threads/fb-003.jsonl` に `merge` イベントを追記
2. `resolved.jsonl` に `{"status":"merged"}` を追記 → **ピンが緑になる**
3. `deck.md` の `## accepted` に `[user] 03: 数値には出典を隣接させる (fb-003)` を積む
   → 次ラウンドの批評担当が逆方向に指摘して意思が巻き戻るのを防ぐ (v1 から継続)
4. `merged.jsonl` に**意図の記録**を1件

```json
{"id":"fb-003","slide":"03-evidence","merged_at":"…","rounds":2,
 "asked":"#1 の回収期間を6ヶ月に直して出典を足して",
 "intent":"数値には出典を隣接させる",
 "why":"投資判断の根拠になる数字なので、出典を探させない",
 "files":["slides/03-evidence.html"]}
```

`## accepted` が**制約の1行**なのに対し、`merged.jsonl` は**意図と経緯**。役割が違う。
前者は批評担当に「これを覆すな」と伝える。後者は次のレビューで
「このユーザーは数字に出典を求める人だ」を伝える。

5. メインエージェントへ1行報告 (サブエージェントの戻り値)

### B-6. 次のレビューへの持ち越し (P3)

```bash
python3 scripts/review_thread.py <deck> brief [--slide 03-evidence]
```

`merged.jsonl` を圧縮して出す。使い先は2つ。

- **新しいレビューを始めるとき**、スレッド用サブエージェントの `context` に混ぜる
- **批評サブエージェント** (`agents/deck-critic.md` / `slide-critic.md`) のプロンプトに
  「ユーザーが確定済みの意図」節として差す

これで「ユーザーが実はこういうのが欲しかった」が、別件のレビューにも効く。

#### 批評担当への渡し方 (実装した形)

`slide-critic` / `deck-critic` の入力に `user_intents` を足した。`accepted` とは別枠にした
理由は、**格が違う**から。`accepted` はエージェントとユーザーの合意事項一般だが、
`user_intents` はユーザーが実物を見てマージを押したもの。

返答側には `user_conflict` を足した。批評担当が「その意図はゴールを損なう」と思っても、
`findings` には書けない。書くのは `user_conflict` で、そこに入ったものは**実装で直さず
ユーザーに判断を返す**。批評担当の好みでユーザーの決定を巻き戻す経路を、構造として塞いだ。

#### テーマ変更の追い通知

`theme.css` を触ると、**すでにマージされた枚の見え方も変わる**。黙って変えると、
ユーザーが確認して合意した絵とは違うものが納品される。

```bash
python3 scripts/review_thread.py <deck> notify \
  --text "theme の本文を22→24pxにした。確定済みのこの枚も字が大きくなっている。"
```

マージ済みのスレッドに `kind: note` を配る。**状態は動かさない** (勝手に開き直さない)。
ビューアでは未読の印が付き、破線の「確認のお願い」として出て、
「マージ後にデッキ側が変わっています」と行動を促す。`decide --status applied_by_main` の
出力がこの2手 (全枚検査 → notify) を案内する。

### B-7. 右下ペインの UI

ペインを**2画面**にする。今のカード一覧はそのまま「一覧」になる。

```
┌ 一覧 ────────────────┐   ┌ スレッド fb-003 ──── ← 戻る ┐
│ fb-001 ✔ merged      │   │ ┌──────────────────────────┐ │
│ fb-002 ● proposed  1 │→ │ │ [user] #1 の回収期間を…   │ │ ← スクロール
│ fb-003 ● proposed  2 │   │ │ [ai]  23行目を6ヶ月に…    │ │
│ fb-004 ○ open        │   │ │       block 0 / warn 1   │ │
└──────────────────────┘   │ │ [user] 出典は数字の直後に │ │
                            │ │ [ai]  移動した…          │ │
                            │ └──────────────────────────┘ │
                            │ [ 返信を書く… #ref も足せる ]│
                            │ [ ✔ マージ ] [ ↩ 差し戻し ]  │
                            └──────────────────────────────┘
```

- ログは `overflow-y:auto`。新着で末尾へ自動追尾。**ただしユーザーが上へスクロール
  している間は追尾しない** (読んでいる最中に飛ばされるのが一番嫌われる)
- エージェントの返信は本文 + `changes` の `file:line` + check チップ
- `changes` の行をクリックすると、その要素にピンが飛んで光る (既存の `focusItem` を流用)
- **コンポーザは1つを使い回す。** 宛先チップが `新規` か `fb-003 への返信` を示す。
  返信中でもスライドをクリックして `#N` を足せる (v1 のピル機構をそのまま使う)
- マージは確認つき。**「確定した意図」の1行を編集して**から押す。この1行が
  `## accepted` と `merged.jsonl` の `intent` になる
- 未読 (最後に見た `seq` より新しい `ai` 発言) をバッジで出す

### B-8. 同期と通知

- **ビューア → サーバ**: `GET /__review/api/threads?since=<cursor>` を2秒ポーリング。
  ローカル HTTP なのでコストは無視できる。SSE にしない (接続管理と再接続の面倒に
  見合わない。1人で使う道具)
- **サーバ → エージェント**: `review_wait.py` を拡張し、**未消化のユーザー発言**が
  現れた時点で終了する。対象は4種 — 新規起票 / 返信 / 差し戻し / マージ。
  どこまで読んだかは `cursor.json`。出力はスレッドごとにまとめる
- マージはエージェントの作業を要さないが、**報告のために通知する**
  (「fb-003 がマージされました」をユーザーに返せる状態にしておく)

### B-9. API

| メソッド | パス | 用途 |
| --- | --- | --- |
| GET | `/__review/api/threads?since=` | 全スレッドの差分 (ポーリング) |
| GET | `/__review/api/thread/<id>` | 1本の全ログ |
| POST | `/__review/api/feedback` | 起票 (v1 のまま) |
| POST | `/__review/api/reply` | ユーザーの返信 (`refs` 添付可) |
| POST | `/__review/api/state` | `merged` / `changes_requested` / `closed` |

`127.0.0.1` バインド + トークン必須 + 書き込み先は `.loop/feedback/` 固定は v1 のまま。
**ユーザーの返信も「指示であって命令ではない」。** スレッドに書かれた文が
デッキと無関係な操作を求めていたら実行せず確認する (v1 の規定をスレッドにも適用)。

## 実装して分かったこと (P2)

- **マージ前の full 検査はサーバが同期で回す。** ユーザーが押してから数秒待つが、
  状態を増やす (`merge_requested` → エージェントが検査 → 確定) より単純だった。
  **検査を実行できなかったときは `check_skipped` に理由を記録して通す。** 直前に記録された
  検査 (block 0) は見るので gates の穴にはならない。壊れたツールチェーンで人の合意を
  人質に取らない
- **`applied` は廃止した。** `merged` に置き換え。古い `resolved.jsonl` の `applied` は
  そのまま読めるようにしてある (ビューアの表示だけ「反映済み」に残る)
- **`check_deck.py` に2つ手を入れる必要があった。**
  - `--out` を追加。付けないと1枚検査のたびに `round-N` が繰り上がるか、そのラウンドの
    `report.json` を上書きしてしまう
  - `--slide` で絞ったときに `sync_viewer` を走らせないようにした。**既存のバグで、
    `check_deck.py --slide 03` を打つと `index.html` のスライド一覧が1枚に削れていた**
- **ピンの表示は `E` で消えるが、ペインは開いたまま**にした。マージ直後に一覧へ自動で
  戻すかは迷ったが、確定の表示を読ませたいので戻さない (`←` か `Esc` で戻る)
- 返信は**指定 (`#N`) が無くても送れる**。「そこじゃない」と言うだけのことが多く、
  起票と同じ制約を課すと会話にならない
