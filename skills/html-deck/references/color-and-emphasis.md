# 色と強調 — 色は装飾ではなく対応表

## 1. 対象と前提

手順3 (theme.css の TOKENS を決める) と手順4 (全枚を実装する) で読む。

このファイルが持つのは **どの色を・どれだけの面積で・何の意味で置くか** だけ。
隣接する契約とは次のように分担している。重複して書かない。

| 決めること | 持ち主 |
| --- | --- |
| コントラスト比・文字サイズ・1枚の情報量 | `quality-contract.md` |
| 余白の配分・構図フレーム | `whitespace-theory.md` |
| job からの構図選択・連続する枚の扱い | `layout-playbook.md` |
| 図の方式選択・図中の数値契約 | `figures.md` |
| **色の面積配分・意味づけ・強調の手段** | **このファイル** |

根拠は、日本語のプレゼン資料4本157枚をOOXMLで実測した結果による。
以下の数値は推測ではなくその実測値で、PowerPoint 資料から取ったものを
1600x900 の HTML デッキ向けに読み替えてある。

測り方と生データは別スキル `pptx-design-system` の design-theory.md にあるが、
このファイルは単体で完結している。**そちらを読みに行く必要はない** (入っていないこともある)。

## 2. 色数ではなく面積で決める

`theme.css` の制約は「配色4〜6色」だが、これは**色数の上限**であって配分ではない。
数えるのは地と本文 (`--bg` `--ink`) を除いたトークンで、`--accent` の濃淡 (下記) は
同じ色相なので数えない。9節の例なら `--surface` `--muted` `--line` `--accent` `--neg` の5色。
実測した4本はいずれも、1色が画面を支配する構造になっていた。

| 資料 | 主役色の参照回数 | 2位 |
| --- | ---: | ---: |
| A | 1,318 | 595 |
| B | 875 | 346 |
| C | 395 | 200 |

目安の面積比は **無彩色 70% / `--accent` 25% / 意味色 5%**。

- 無彩色は `--bg` `--surface` `--ink` `--muted` `--line` の5つ。これが画面の地になる
- `--accent` が主役でいられるのは、周りが無彩色だから。全面に散らすと主役が消える
- 意味色 (4節) は5%しか出ない。**常時5色を宣言する必要はない**

色数を増やしたくなったら、まず `--accent` の濃淡で足りないかを疑う。
濃淡は**計算した16進数をトークンとして宣言する** (`--accent-20: #d3e0fb;`)。
スライド側で `color-mix()` を書くと、検査は計算後の色をトークン外として `palette_drift` で拾う。

- 面として見せる淡色は **20%以上**。9% 程度だと白地との差が見えず、強調の面にならない
- 淡色の上の文字は `--ink` にする。`--accent` の文字を同系の淡色に載せると、
  4.5:1 をわずかに割りやすい (実例: 4.49:1)。載せるなら比を測ってから

## 3. 主役の色は題材から取る

`--accent` を「好きな色」で決めない。実測した4本はいずれも題材側から取っていた。

- 題材のブランド色をそのまま使う (Obsidian の回 → Obsidian の紫)
- **使うイラスト素材の既定色に合わせる**。unDraw なら `#6C63FF`
- ロゴから最も面積の大きい色を取る

2番目が特に効く。ある資料は `--accent` が unDraw の既定色と同じで、
挿絵・図版・本文の強調がすべて同じ色で喋っていた。素材を後から塗り直す手間も出ない。

このデッキで画像やイラストを使うなら (`image-selection.md` で要否を決めたあと)、
**素材の色を `--accent` に合わせるか、`--accent` を素材に合わせるか**を先に決める。
どちらでもよいが、決めずに進めると図だけ色が浮く。

## 4. 意味を色に固定する

装飾で色を選ばない。実測した4本は、4本すべてで同じ対応を守っていた。

| 意味 | 提案トークン | いつ出すか |
| --- | --- | --- |
| 否定・リスク・課題 | `--neg` | ×印、できないこと、失敗のコスト |
| 肯定・達成・解決 | `--pos` | ○印、効果、できるようになること |
| 注目させる数値 | `--focus` | グラフの当該系列、主要な数字1つ |
| 参照・外部・引用 | `--info` | 他社、引用元、補足リンク |
| 中立・抑制 | (既存の `--muted` / `--surface`) | 比較対象、採らなかった選択肢 |

`theme.css` の `--accent-2` はこれらとは別で、意味を持たない第2系列・対比用。
意味色の代わりに使わない。「否定を `--accent-2` で」とやると、5節の対応表が崩れる。

**実際に出番のあるものだけを宣言する。** 1本のデッキで本当に使うのは多くて2つで、
5つ並べた時点で「配色4〜6色」を超える。中立にトークンは要らない —
文字は `--muted`、面は `--surface` で足りる。

赤は否定の色として予約する。**目立たせたいだけの赤を使わない。**
注目させたいなら `--focus`、主張したいなら `--accent`。
この区別を崩すと、赤が出ても読み手が危険だと思わなくなる。

意味色も本文と同じコントラスト契約に従う (`quality-contract.md`: 4.5:1、32px以上は3.0:1)。
`--neg` を薄い赤にすると、警告なのに最初に読めなくなる。

## 5. 登場人物に色を固定する

図が複数枚にまたがるとき、**同じ対象には最後まで同じ色**を当てる。

実測した資料では「新卒社員 = 青 / 会社 = 緑」が、問題提起の図・ビジネス展開の図・
システム構成図と、別々の枚をまたいで一度も崩れていなかった。
読み手は2枚目から凡例を見なくなる。これが色を対応表として使うということ。

デッキ単位で決めて `deck.md` の `## design` に書き残す。

```
登場人物の色: 自社=--accent / 競合=--muted / 顧客=--info
```

インラインSVGで図を書くときは、この対応も `var()` 経由で書く。
`figures.md` の「色 — theme のトークンのみ」と同じ理由で、
図だけ生の16進数を書くとデッキの声が割れる。

## 6. 強調の手段は3つ

### 色で差す — 太字ではなく

実測では、太字のランは全体の **3〜14%** しかなかった。
一方で色を変えたランは1資料あたり13〜38回あった。和文は太字にすると字面が崩れるので、
**文の中で一番効く語だけを1色**にするほうがリズムを壊さない。

```html
<p>新入社員の<em>適切な配属先</em>を見極められる</p>
<!-- em { color: var(--accent); font-style: normal; font-weight: inherit } -->
```

これは**本文とリード文**の話。主張文 (見出し) の中の1語は色で差さない — 見出しはすでに
その枚で一番強く、1語を塗ると見出し全体より先にその語だけが読まれる。
色を差すなら見出しの下の1文に置く。否定の語なら `--neg`、それ以外は `--accent` (4節)。

斜体は和文で使わない。`font-style: normal` を明示して潰す。

### 他を落とす — 消さない

採らなかった選択肢を消さず、`--muted` と `--surface` で沈めて残す。
検討の幅がそのまま説得力になる。

ただし**落とした側も読めること**。`--muted` は `--bg` に対して 4.5:1 以上という
theme.css の契約がここにも効く。グレーアウトは「読ませない」ではなく「主役ではない」。

### 積み上げる — 同じ構図のまま足す

同じ構図を保ったまま、1枚ごとに要素を足して2〜3枚続ける。
読み手は毎回見方を覚え直さずに済み、増えた分だけに注意が向く。

**`layout-playbook.md` の「同じ形が3枚続くと情報が増えていないと感じる」と衝突して見えるが、
別のことを言っている。** 見分ける問いは1つ。

> 前の枚と比べて、絵の中身が目に見えて増えているか。

- 増えている → 積み上げ。同じ構図は**増分を読ませるための装置**として働いている
- 増えていない → `layout-playbook.md` が警告している失敗。形ではなく内容の切り分けを直す

上限は両者で共通して **3枚**。さらに図のある枚で積み上げるなら、
`figures.md` の「図のある枚を3枚以上続けない」が効くので **2枚まで**。

## 7. 線で分けず、面で分ける

`--line` の出番を絞る。箱を細い罫で囲むと、読む前に「要素がいくつあるか」が先に目に入り、
情報量が増えていないのに増えたように見える。

| やること | やらないこと |
| --- | --- |
| `background: var(--surface)` で地より一段沈める | `border: 1px solid var(--line)` で囲む |
| 表は見出し行の地色と行の交互塗りで分ける | 表に縦罫・横罫を引く |
| 間隔で群を分ける (`whitespace-theory.md`) | 群の区切りに飾り罫を入れる |

`--line` を使ってよいのは、グラフの軸と、紙に近い色面の輪郭だけ。

`theme.css` の既定 `--surface: #f4f6f9` は白地に対してかなり薄い。
罫なしで面として読ませるなら、`#eef0f4` 程度まで一段暗くする。
面が見えないまま罫を足すと、結局カードUIに戻る。

`theme.css` の `--radius` は既定が `0px`。角丸を使うなら2種類まで
(ピル = 半径最大、カード = 浅い) にして、それ以外は作らない。
影・グラデーション・立体表現は使わない。面の差は明度だけでつける。

## 8. 文章量との関係

`quality-contract.md` の予算は「話しながら見せる」で300字。これは**上限**である。

実測した4本の1枚あたり文字数は、**中央値が64〜125字**、
9割の枚が250〜400字以内に収まっていた。
予算いっぱいまで使うのは例外であって、標準ではない。

色の話に戻ると、これは強調が効く条件でもある。
1枚300字を埋めてから1語を色で差しても、その1語は埋もれる。
**強調は、強調していない部分があって初めて効く。**

## 9. theme.css への書き方

手順3で決めたら、TOKENS にこう置く。宣言するのは使うものだけ。

```css
:root {
  /* 無彩色 — 画面の7割 */
  --bg:      #ffffff;
  --surface: #eef0f4;   /* 面。白地の上で境界が見える明度に置く */
  --ink:     #14181f;
  --muted:   #5a6474;   /* --bg に対して 4.5:1 以上 */
  --line:    #d3d9e2;   /* 軸と色面の輪郭だけ */

  /* 主役 — 画面の2.5割。題材か素材から取る */
  --accent:  #6c63ff;

  /* 意味色 — 画面の0.5割。このデッキで出番があるものだけ宣言する */
  --neg:     #c00000;
}
```

決めた対応は `deck.md` の `## design` に日本語で残す。
次に直すときに「なぜこの色なのか」を読み返せないと、2枚目から崩れる。
