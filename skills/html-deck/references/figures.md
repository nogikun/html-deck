# 図と画像

スライドで図が効くのは、**文章で書くと関係が見えないとき**だけ。
箇条書きで足りるものを図にすると、情報は増えないのに読む手間だけ増える。
先に「この関係は文字で書けるか」を自問し、書けるなら図にしない。

ただし逆向きの失敗のほうが多い。**関係が書かれているのに文字のまま**という枚が並ぶと、
どの1枚も検査を通ったままデッキ全体が文字の壁になる。検査は並びとして測る
(`figure_coverage`: 図のある枚が4割以上 / `text_only_streak`: 図のない枚は2枚まで)。
数値の根拠は `references/quality-contract.md`。**通すために飾りを足すのではなく、
箇条書きに書いてしまった関係を図に移す。**

## 1. 方式を選ぶ

上から順に当てはめ、**最初に当たったものを採る**。複数条件で迷わないように順序で決める。

| 順 | 方式 | 条件 |
| --- | --- | --- |
| 1 | **ラスタ画像** (png/jpg) | 写真・実画面のスクリーンショット・ロゴ。**現実の見た目そのものを見せる**とき |
| 2 | **draw.io → SVG** | 線が交差する。または**箱が7個以上**。または ER / シーケンス / C4 のように定型がある |
| 3 | **インラインSVGを手で書く** (既定) | 上のどれでもない。箱6個以下で、線が交差しない |

「箱」はノードだけを数える。線は数えない。
**線の交差は箱の数より優先する。** 箱が4個でも矢印が交差するなら draw.io を使う。
交差の取り回しは手作業だと必ずずれるので、そこは道具に任せたほうが速い。

図の代わりにラスタ画像を置かない。構造を説明したいなら図を描く。
スクリーンショットの中の文字は 1600x900 に縮めるとまず読めない。

**どの方式でも、最終的にHTMLへ書くのはインラインSVGかラスタ画像**。
`<img src="figure.svg">` にはしない。理由は3つある。

1. `<img>` の中身はDOMから見えない。文字サイズもコントラストも重なりも測れず、
   このスキルの検査が図に対してだけ無力になる
2. インラインなら図の色を `var(--accent)` で書ける。配色を変えたときに図だけ取り残されない
3. 外部ファイル参照が1つ減る。CSPとオフライン配布の面でも素直

**Mermaid は下書きまで。** 構文としては安定するが、レンダラがJavaScriptで
`script-src 'none'` のスライドでは描画できず、レイアウトも自動決定なので
1枚の伝達ゴールに配置を寄せられない。意図の確認には使ってよい。

**直接SVGを書いてよいのは、測って直す前提があるから。** LLMは座標計算でラベルを重ね、
矢印をずらす。これは描画結果を見せて直させると改善することが分かっていて、
このスキルは最初からその形 (描く → 1600x900でレンダリング → 実効サイズ・重なり・
枠外・線幅を実測 → 絵を批評役に見せる) になっている。**一発で描き切ろうとしない。**

## 2. 配置パターン

作業領域は 1600x900 から余白を引いた **1440x796**。

### A. 図が主役 — job が 構造 / 因果 / 数量 のとき

```text
┌──────────────────────────────────────────┐
│ 問い                                 01/08│
│ 見出し (1行で言い切る)                    │
│ ┌──────────────────────────────────────┐ │
│ │                                      │ │  図: 幅1160〜1440 / 高さ400〜520
│ │              図                      │ │  画面の 35〜55%
│ │                                      │ │
│ └──────────────────────────────────────┘ │
│ キャプション (図から読み取る一文)          │
│ MEASURED …                               │
└──────────────────────────────────────────┘
```

文章は**キャプション1本だけ**。図の横に解説を足したくなったら、
それは図が語れていない証拠なので、図のほうを直す。

### B. 図と読み解きの対 — 図だけでは結論が出ないとき

```text
┌────────────────────────────┬─────────────┐
│                            │ 読み取れること│
│          図 940px          │ ・ 1行       │  非対称 940 / 40 / 460
│                            │ ・ 1行       │  均等割りにしない。
│                            │ ・ 1行       │  主従が消える
└────────────────────────────┴─────────────┘
```

### C. 並置比較 — 2つの図を比べさせるとき

```text
┌──────────────┐   ┌──────────────┐
│   図 A       │   │   図 B       │   700 / 40 / 700
│  (同じ縮尺)   │   │  (同じ縮尺)   │   viewBox の高さと
└──────────────┘   └──────────────┘   縮尺を必ず揃える
```

**縮尺を揃えないと、差が図形の差として見えない。**
数量を比べるなら軸の原点も共有する。片方だけ原点を切ると差が誇張される。

### D. ラベルは図の外に出す

小さい箱の中に文字を詰めるより、箱の外に引き出したほうが読める。
図の中の文字は viewBox で縮むので、実効20pxを割りやすい。
**箱の中に入れるのは名前だけ、説明は外。**

### E. 全面図 — 1枚まるごと1つの図

見出しを図の空きに重ねる。図が画面の70%以上を占める。
デッキに1〜2枚だけ使う。連発すると図の重みが平準化する。

### 連続させない

図のある枚を3枚以上続けない。同じ形が続くと情報が増えていないと感じられる。
図と文字の枚を交互に置くと、図の枚が際立つ。

## 3. 図の中の数値契約

`tools/src/html_deck/assets/gates.json` に入っていて、`html-deck-check` が実測する。

**色帯の上に白抜き文字を置かない。** コントラストの背景は DOM の祖先の `background-color` を
辿って決めるので、SVG の `<rect fill>` は背景として数えられない。帯を濃色で塗ってその上に
`--on-accent` のラベルを置くと、実際には読めていても本文色 対 ページ背景で測られて
`low_contrast` で落ちる。ラベルは帯の外に出すか、帯と同系の濃い文字色にする。

| 項目 | 基準 | 判定 | なぜ |
| --- | --- | --- | --- |
| 図中の文字 | 実効 **20px** 以上 | 20px未満 review / 14px未満 block | 地の文より一段小さくてよいが、それ以上は読まれない |
| コントラスト | **4.5:1** (32px以上は 3.0:1) | block | **図の中も本文と同じ基準**。薄い線色のラベルはここで落ちる |
| 線の太さ | 実効 **1.5px** 以上 | review | 0.5pxの線は投影とPDFで消える |
| 文字の重なり | **ゼロ** | block | 座標指定の事故。通常の組版では起きない |
| 枠外要素 | **ゼロ** | block | SVGは枠外を描かない。その分は黙って消える |
| 図の内側余白 | **24px** 以上 | review | 縁に触れる要素は切れて見える |
| ラスタ解像度 | 表示幅の **1.5倍** 以上 | 1.5倍未満 review / **等倍未満 block** | 1600x900は等倍でも大きい |
| 縦横比 | 元画像から **2%** 以内 | review | 潰れた図は内容より先に目につく |
| 色 | theme のトークンのみ | review | 図だけ別の色を使うとデッキの声が割れる |
| 名前 | `<title>` か `aria-label` | review | 図が主張を持つなら読み上げられる必要がある。装飾なら `aria-hidden="true"` |

`figcaption` は図の中ではなく**注記**として扱われる (下限18px)。
図の外に置く説明文なので、図中文字の20px契約は当たらない。

**実効サイズは指定値と違う。** `viewBox="0 0 1200 400"` を幅600pxで表示すると倍率0.5倍で、
`font-size="20"` は画面上10pxになる。検査はこの実効値で判定し、
指摘には倍率も出す。SVG側の数字だけ見て直すと直らない。

### 図をトークンで書く

```html
<style>
  .node { fill: var(--surface); stroke: var(--ink); stroke-width: 2; }
  .lbl  { fill: var(--ink); font-family: var(--body); font-size: 26px; font-weight: 700; }
  .link { stroke: var(--ink); stroke-width: 3; fill: none; }
</style>
<svg viewBox="0 0 1160 380" role="img"><title>図が何を示しているか</title>
  <rect class="node" x="6" y="60" width="330" height="200"/>
  <text class="lbl" x="38" y="130">実測</text>
</svg>
```

`fill="#101418"` のような直値を書くと `palette_drift` で出る。

## 4. draw.io を使う手順

上流スキルを `vendor/draw-io/` にそのまま同梱してある
(MIT / little-hands。取り込み元と差分は `vendor/draw-io/VENDOR.md`)。

1. `vendor/draw-io/SKILL.md` と `vendor/draw-io/references/` を読む。
   `.drawio` XMLの書き方と座標計算はそちらが正本
2. `deck/figures/<name>.drawio` を書く。
   **`<mxGraphModel darkMode="0">` を必ず入れる** — 無いとSVG書き出しで色が反転する
3. 色は theme のトークンと同じ16進値を直接書く (draw.io XML では `var()` が使えない)。
   例: `fillColor=#eef1f5;strokeColor=#101418;fontColor=#101418`
4. 文字は **`fontSize=22` 以上**、`fontFamily=Hiragino Sans` を明示する。
   実効20pxの契約に対して余裕を持たせる値。縮小して貼るなら
   `22 × (表示幅 ÷ viewBox幅) ≥ 20` を満たすように逆算する。
   線も `strokeWidth=2` を明示する (既定の1pxは実効1.5pxを割る)
5. SVGへ書き出す

   ```bash
   uvx --from <このスキルのディレクトリ>/tools html-deck-drawio <deck>/figures/<name>.drawio --title "図の説明"
   ```

   `width`/`height` を外して `viewBox` を残し、`color-scheme` を除き、
   `role="img"` と `<title>` を付けた状態で出る
6. 出たSVGの中身をスライドの `<figure>` へ**そのまま貼る**
7. `html-deck-check` で実効文字サイズ・重なり・線幅・色まで測る

draw.io 本体が無い環境では `html-deck-drawio` がその旨を出して止まる
(macOS: `brew install --cask drawio`)。無い場合は方式Aの手書きSVGに寄せる。

## 5. よくある失敗

- **図を描いてから内容を決める** — job を決めてから形を選ぶ。逆順だと、
  思いついた見た目に内容を押し込むことになる
- **一発で描き切ろうとする** — 座標は必ずずれる。描いて、測って、直す
- **凡例で色分けだけを使う** — 色覚特性とモノクロ印刷で消える。形かラベルを併記する
- **図の中に本文を書く** — 図は関係を見せる場所。文は figcaption か本文へ
- **draw.io の既定色をそのまま使う** — `#dae8fc` のような既定色が残ると palette_drift で出る
- **スクリーンショットを図の代わりに貼る** — 実画面を見せる目的なら正しいが、
  構造を説明したいなら図を描く。スクリーンショットの中の文字はまず読めない
