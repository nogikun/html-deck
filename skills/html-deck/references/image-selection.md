# 主張を支える画像を選ぶ

画像は、実物・実画面・具体例を見せることで `claim` の理解が進む場合に使う。
図の枚数を増やすための装飾写真は入れない。構造・因果・数量を示すなら、まず図やグラフを選ぶ。
専用モデル・追加ライブラリ・画像用のmanifestは不要。既存エージェントの視覚確認と
`deck.md` の記録で進める。画像内文字や操作部品を読ませる場合の配置記録は
`references/image-layout.md` に従う。画像カタログや専用の認識環境は作らなくてよい。

## 選ぶ前に確認する

### 画像を使うと、何が伝わりやすくなるか

画像探しから始めず、まず「この枚で読者に分かってほしいこと」を `claim` から決める。
画像を外した案と比べ、実物の識別・操作場所・関係・数量差など、何が理解しやすくなるかを1文にする。
本文の言い換えや雰囲気づくりだけなら、画像なしでよい。図の割合を満たすための装飾は足さない。

| 見せたいもの | 第一候補 | 選ぶ理由 |
| --- | --- | --- |
| 実際の画面・製品・現場の姿 | 実画面や実物の画像 | 見た目や操作場所そのものが必要 |
| 手順・構造・比較の関係 | 自作の図 | この枚に必要な関係とラベルへ絞れる |
| 記事・論文が示した測定結果や独自の図 | 元の図の引用、またはデータからの作図 | 根拠との対応、条件・軸・凡例を正確に示す必要がある |
| 著者の定義・主張の言い方 | 必要な文章の短い引用 | その表現自体を検討・説明する必要がある |
| 記事の内容を紹介するだけ | 自分の言葉による要約と出典 | 原文の表現や図をそのまま見せる必要がない |
| 一文の結論だけで伝わる | 画像なし | 読み手が余分な画像を解釈せずに済む |

これは固定テンプレートではない。同じ記事でも、理解したいのが数値か仕組みかで選択は変わる。
判断はstoryboardの `visual` と `deck.md` に短く残す。全枚に画像や引用を要求しない。

### 既存記事から引用するべきか

1. まず提供された資料と既存の出典を確認する。足りない証拠や実例がある場合だけ、元の記事・
   公式資料・論文などを探す。画像検索のサムネイルや検索要約だけで採用しない。
2. 元ページと図・本文を実際に読み、`claim` を支えるかを確認する。
   原図の測定条件・比較軸・著者の表現自体が重要なら引用を候補にする。
3. 関係を簡潔に説明したいだけなら、自作の図を検討する。数値や主張を出典から得た場合は、
   自作しても出典を残す。元図をなぞったものを、独自の成果として見せない。
4. 文章で足りる場合は、図や記事全体のスクショを貼らず要約する。
   原文の言い方が必要な部分だけは、引用と分かる形で自分の説明と区別する。
5. 外部の図・写真・文章を使う前に、出典と利用条件を確認する。出典を書くだけで自由に転載できるとは扱わない。
   素材の使用条件を確認できない場合は自動採用せず、確認できた事実の要約と出典などで説明する。

引用するなら、著者・記事名・URL・公開日や版・図番号等を `deck.md` に残し、
スライドにも出典を付ける。省略・切り出し・翻訳・作図し直した場合は、その旨も記す。
図の軸・凡例・前提を落として元の意味を変えない。過去の画面を現在の操作例として見せる場合は、
時期や版が合うかも確認する。読める大きさを確保できなければ拡大・分割・別の表現を選ぶ。

### 候補を確認する

1. storyboard の `claim / job / visual / evidence` から「何が写っていれば説明になるか」を1文にする。
2. 提供素材や調査で見つけた候補を実際に見る。画像を見られない環境では、人手の説明や
   信頼できる文書のキャプションを使う。ファイル名・寸法だけで内容を断定しない。
3. 内容の一致、出典と利用条件、必要な文字や被写体の可読性を確認する。
   出典や利用条件を確認できない外部画像は採用しない。ユーザー提供というだけで
   外部への再配布が許可されているとは扱わない。
4. 条件を満たした候補から、主張を最も具体的に支え、必要情報を切らずに置けるものを選ぶ。
   選べなければ画像なしでよい。意味の一致を架空の数値スコアで表さない。

採用した画像と、検討して見送った候補について、`deck.md` に短く記録する。
全フォルダの索引は作らない。

| slide | 候補 | 内容の確認方法 | 採用・不採用の理由 | 出典・利用条件 |
| --- | --- | --- | --- | --- |
| 03-login | assets/images/login.png | エージェントが実物確認 | 採用: 入力欄と送信ボタンを見せる。全体をcontainで配置 | ユーザー提供の自作画面、配布範囲確認済み |
| 03-login | login-old.png | ファイル名のみ | 不採用: 対象の画面か確認できない | 未確認 |

画像を見たという記録は、画像内の数値や事実の正しさまで保証しない。
実測結果の証拠と説明用のイメージを区別し、例示画像を実際の成果のように見せない。

## 配置して確認する

切り抜き方針と配置は `references/figures.md` に従う。
画像内の文字・操作部品を読ませる場合は `references/image-layout.md` も読む。
主役画像＋短い説明、画像と解説の左右配置、同じ縮尺の並置比較から、jobに合う構図を選ぶ。
迷ったときだけ少数案を比べる。全枚で複数案を作ることは必須にしない。

採用画像はデッキ内の `assets/images/` に置き、スライドからの相対パスで
`figure > img` として参照する。内容を表す `alt` と、必要な説明・出典の `figcaption` を付ける。
主要な画像を CSS の背景にするとPPTX抽出の対象にならないため、`img` を使う。

`html-deck-check` の後、スクリーンショットで主役の欠損、画像内の文字、背景と文字の重なりを
確認する。現行の機械検査は、意味の一致・被写体の保護・写真上の局所コントラストを保証しない。
画像と選定記録を `agents/slide-critic.md` の批評へ渡す。

単一HTMLでは画像の埋め込み、PDFでは画像の表示を確認する。
**現行PPTX出力は `object-fit` / `object-position` を再現しない。** PPTXを出す場合は
HTMLとの見比べが必要。差があれば元画像比率に合う表示枠へ直すか、必要情報を保った
加工済み画像を使い、修正後も確認する。残った差異は納品時に明記する。

## 判断を確かめる例

以下は画像を扱う際の確認例。自動テストや実施済みの評価結果ではない。

| ケース | 期待する判断 |
| --- | --- |
| 写真: 実物が主張の具体例になる | 内容を確認して採用。主役を切るcoverは避ける |
| スクリーンショット: 操作対象を示す | containで入力欄・ボタン・文字を残す。読めなければ拡大・分割する |
| ロゴ: 対象サービスを識別する | 縦横比と全体を保持し、ロゴを効果や実績の根拠にしない |
| グラフ画像: 数量差を示す | 軸・凡例・出典を残す。縮小して読めなければ描き直す |
| 比較: 改修前後の画面 | 同じ表示枠・縮尺・対応範囲で並べる |
| 内容不明: ファイル名だけ関連する | 内容を推測して採用せず、不採用理由を残す |
| 記事の図: 原図の実験結果を説明する | 元ページと条件を確認し、引用とデータからの作図を比較する |
| 記事の文章: 著者の表現自体が必要でない | 内容を要約して出典を残し、長文や記事全体のスクショを貼らない |
| 装飾写真: 主張の理解に寄与しない | 画像なしを選ぶ |
