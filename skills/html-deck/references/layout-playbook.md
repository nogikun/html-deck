# レイアウトの手がかり

**テンプレート集ではない。** 型を配ると全枚が同じ顔になり、このデッキの伝達ゴールに
合わせる余地が消える。ここにあるのは「その枚が何をしようとしているか」から
形を決めるための取っ掛かりで、そのまま使うことは想定していない。

## 形は job から決める

各スライドの `job` を先に確定させてから形を選ぶ。逆順にすると、
先に思いついた見た目に内容を押し込むことになる。

| job | 読者にさせたいこと | 形が体現すべきこと | よくある失敗 |
| --- | --- | --- | --- |
| 宣言 | 1つの結論を持ち帰る | 画面の大半を1つの文が占める | 結論の周りに根拠を詰めて主張が埋まる |
| 比較 | AとBの差を見る | 2つが同じ軸で横に並び、差そのものが図形として見える | 左右に箇条書きを2つ置いただけ |
| 因果 | 順序と向きを追う | 進行方向が1つに定まる。矢印は方向の証拠であって装飾ではない | 全方向に矢印が伸びて順序が消える |
| 構造 | 部分と全体の関係を掴む | 包含・階層が入れ子や位置で表れる | 平らな箱を並べて関係を線で補う |
| 数量 | 大きさの差を体感する | 数値の差が面積か長さの差として出る | 数字を文字で並べて差が見えない |
| 例示 | 抽象を具体で確かめる | 具体物が主役で、説明が脇に退く | 説明が主役で例が注釈になる |

## 視線の入口を1つにする

3秒で分かるとは、**最初に目が行く場所が1箇所に決まる**ということ。
決めるための手段は大きさだけではない。

- 大きさ — 最大要素は1つだけ
- 位置 — 上か左に置いたものが先に読まれる (日本語・英語とも)
- 色 — 強調色を1箇所だけに使う
- 余白 — 周囲が空いているものは大きくなくても目立つ
- 密度差 — 密の中の疎、疎の中の密

これらを2つ以上同時に同じ場所へ効かせる。別々の場所に効かせると入口が割れる。

## グリッド

1600x900 の内側、padding を引いた作業領域はおよそ 1440x796。
そこを均等に割るときの取りやすい数:

- 2分割 (比較): 700 / 40 / 700
- 3分割 (段階・並列): 456 / 36 / 456 / 36 / 456
- 非対称 (主従): 940 / 40 / 460 — 主と従を明確に分けたいとき
- 縦: 見出し帯 / 本体 / 出典帯 の3段。本体に高さを最大に割く

均等分割は安全だが平板になる。**主従があるなら非対称にする。**
3つとも同じ重要度で本当に並列なとき以外、3分割は情報を平坦化する。

## 構図フレームを先に割る

グリッドの数値を決める前に、親の内側幅 `A` を確定する。横配置は
`Σ内容幅 + Σ親gap = A` とし、親gapと子の左右marginで同じ間隔を二重に払わない。
比較や表の固定幅フレームは `margin-inline:auto` で中央に置く。

```css
/* 1600pxキャンバス、左右80pxの作業領域 */
.split {
  width: 1440px;
  margin-inline: auto;
  display: grid;
  grid-template-columns: minmax(0, 1fr) 40px minmax(0, 1fr);
  column-gap: 0;
}
```

2分割の初期値は `700 / 40 / 700`、3分割は `456 / 36 / 456 / 36 / 456`。
中央の40px・36pxは接続や分離のスロットで、矢印の箱そのものを170pxや768pxへ広げない。
コネクタは56〜80pxを開始値、96pxまたは内側幅の12%を上限にする。

### 片寄り・重なりの修復順

`html-deck-check` の `layout_overlap`、`composition_off_center`、`layout_child_shift`、
`connector_track_wide`、`redundant_gap_owner` は、子の座標を微調整する指示ではない。
次の順に親を直す。

1. 親に `data-space-frame="composition"` を付け、内側幅と軸を決める。
2. 兄弟の内容幅と分離スロットの合計を、親の内側幅へ収める。
3. 固定の空き列を `minmax(0, 1fr)` へ戻すか、内容に合う固定幅へ縮める。
4. 中央構図は `margin-inline:auto`、意図した左寄せは `data-space-intent="left"` で宣言する。
5. `left`、`right`、`transform`、過大な矢印列を削って再検査する。
6. 収まらない場合は空白を詰めず、縦積みかスライド分割に戻す。

親子の包含は正常なので重なりに数えない。比較するのは同一フレームの直接の兄弟だけで、
意図したレイヤー表現だけ `data-space-intent="overlay"` を付ける。

## 動きを使う場面

固定PDFにすると動きは消える。だから動きは「あると理解が進む」ものだけに使い、
「ないと成立しない」ものには使わない。

使いどころは、順序を持つ情報を順序どおりに出すとき (因果・段階) と、
1枚の中で視線を誘導したいとき。`prefers-reduced-motion` で必ず消えるようにする。
検査は reduced-motion で撮るので、動きの途中が採点されることはない。

## 連続する枚の形を変える

同じ形が3枚続くと、聞き手は「情報が増えていない」と感じる。
これは1枚ずつ作ると必ず起きる失敗なので、実装前にストーリーボードの `job` 列を
縦に読んで、同じ job が3つ続いていないか確認する。続いていたら、
形を変えるのではなく**内容の切り分けを変える**。形だけ変えると、
同じことを違う見た目で言っているだけになる。

## 自分の案を疑う

作る前に、その構成が「このデッキだから」の答えになっているかを見る。
別の題材でも同じ構成を出しそうなら、それは選択ではなく既定値。
既定値になりやすい形は決まっている。

- 中央に大きな数字、下に小さなラベル、周りに補足の3カラム
- タイトル + 3つのカード + 各カードにアイコンと2行
- 左に文章、右にイメージ、を全枚で繰り返す

これらが悪いのではなく、**それを選んだ理由がないまま出てくる**ことが問題。
理由が言えるなら使ってよい。言えないなら、その枚の job に戻って選び直す。

デザインの方向づけそのものは、手順0 で拾ったデザイン系スキルに任せる
(`frontend-design` / `design` / `artifact-design` など、環境にあるもの)。
このファイルは、その方向づけを 1600x900 のスライドという制約に落とすための補助。
