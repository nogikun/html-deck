# 品質契約 — 1600x900 で読める形の数値

しきい値の実体は `tools/src/html_deck/assets/gates.json`。ここはその**根拠**。
根拠を知らずに数値だけ守ると、外すべき場面で外せない。

## なぜ 1600x900 固定なのか

ビューアは内部を常に 1600x900 で描き、ウィンドウに合わせて全体へ同じ倍率を掛ける
(`scale = min(幅/1600, 高さ/900)`)。だから **CSS を可変にする必要がない。**
`clamp()` も `cqh` も使わず px で書き切ってよく、そのほうが実測値と指定値が一致して
評価ループが安定する。

代償として、小さいウィンドウでは文字も小さくなる。保証しているのは
「どの画面でもレイアウトが同一」であって「どの画面でも読める」ではない。
倍率 0.45 未満はビューアが全画面表示を促す。発表環境としては 0.45 未満を許容しない。

## 文字サイズ

検査は文字を2段階に分けて見る。**読ませる文**と、**目印としてのラベル**では
必要な大きさが違うからで、同じ下限を当てると装飾ラベルの修正でループの枠が埋まる。

| 段階 | 何が当たるか | 目安 | 下限 |
| --- | --- | --- | --- |
| 本文 | 25文字以上の地の文 | 24px | **22px** (18px未満は block) |
| ラベル | 25文字未満の見出し語・数値・キャプション | 18–20px | **18px** |
| 細字 | `.slide-footer` `.source` `.caption` `.footnote` `figcaption` 内 | 18px | **14px** |
| 図中 | インラインSVG / `figure` の中の文字 | 22–26px | **20px** |
| 全体 | どんな文字も | — | **14px (絶対下限)** |

図の中の文字は viewBox で拡大縮小されるので、**指定値ではなく実効サイズ**で測る。
図と画像の契約は `references/figures.md` にまとめてある。

| 用途 | 目安 |
| --- | --- |
| デッキタイトル / 数字1つを見せる枚 | 80–96px |
| スライド見出し (h1/h2) | 48–72px、本文の 2.2倍以上 |
| 小見出し (h3) | 32–40px |
| リード文 | 28–32px |

下限の根拠は視力ではなく**縮小耐性**。会議室の共有画面やWeb埋め込みで倍率 0.5 まで
落ちると 22px は 11px になる。これ以下は「読めるが読まれない」状態になる。

細字の枠は出典と注記のためにある。**本文を `.caption` で包んで下限から逃げない。**
検査は通っても、絵を見る批評担当が読めない文字として落とす。

サイズ段階は **7種類まで**。段階が多いほど「どれが重要か」の手がかりが薄れる。
見出しと本文の比が 2.2倍未満だと、視線の入口が決まらない。

日本語の見出しは `word-break: auto-phrase` で文節ごとに折る。これがないと
「ではな / く」のように語の途中で改行され、読み直しが起きる。`text-wrap: balance` と
併せて theme.css の見出しに入れてある。

## 1枚あたりの情報量

- 日本語 **420文字**まで。超えると3秒では読めない
- 箇条書きは **6項目**まで、1項目 **60字**まで
- 1行の長さは日本語 **46文字**、英語 **82文字**まで。超えると行頭に戻れなくなる
- 文字ブロックの面積が画面の **30%** を超えたら、削るか2枚に割る

これらは block ではなく review。長い引用や表を意図的に見せる枚では正当に超える。
超えたときは deck.md の `accepted` に理由を書き、批評担当に判断を渡す。

### 予算は場面で変わる

同じ420字が、話しながら見せる場面では多すぎ、配布資料では少なすぎることがある。
手順1のインタビューで場面を聞いたら、**ラウンド0で1度だけ** `max_ja_chars` を決める。

**反映先は `<deck>/gates.json`。** 同梱の `gates.json` を `<deck>/gates.json` にコピーして、そこを直す。同梱側は uv のキャッシュに展開されるので書き換えられないし、書き換えたら他のデッキにも波及する。デッキの隣に置けば変えた事実がデッキと一緒に残り、`html-deck-check` が自動でそちらを読む。

| 場面 | 1枚の日本語 | 理由 |
| --- | --- | --- |
| 話しながら見せる | **300字** | 画面を読ませると話が聞かれない。画面は話の裏付け |
| 置いて読ませる (配布・非同期) | 420〜520字 | 本文が主。ただし1枚1メッセージは崩さない |
| 両方 | 300字 + 話す内容は deck.md 側へ | 画面に全部載せない |

### 箇条書きは形ではない

**1項目60字を超えたものは、箇条書きの形をした段落**で、読まれない。
検査は `bullet_is_paragraph` として拾う。取れる手は3つ。

1. 体言止めまで削る (「〜することで改善が期待できます」→「〜で改善」)
2. 並列ではなく関係だった場合は図にする。**比較・順序・包含・数量が書かれているなら、
   それは箇条書きではなく図の中身**
3. 本当に読ませる文なら、箇条書きをやめて本文にする

項目数が7つ以上になったときも同じ。並列に見えるだけで順序も重みも伝わらないので、
削るか、図か表に組み替える。

## 図の被覆 — 1枚では測れない情報量

枚ごとの字数が全部範囲内でも、**文字だけの枚が続くデッキは読まれない。**
どの1枚も合格のまま全体が文字の壁になるので、並びとして測る。

| 指標 | 値 | 検査 |
| --- | --- | --- |
| 図のある枚の割合 | **4割以上** | `figure_coverage` |
| 図のない枚の連続 | **2枚まで** | `text_only_streak` |
| 図と数えるサイズ | 画面の **4%以上** の svg / img | (アイコンは数えない) |
| 字数超過の枚の割合 | 4割を超えたら分量そのものを見直す | `deck_too_dense` |

**表紙も章扉も除外しない。** 除外を入れると「これは表紙だから」で毎回抜けられる検査に
なって機能しない。図が3枚連続で無いなら、読み手にはその区間が文字の壁として続く。

応え方は1枚ずつの修正ではない。**どの枚を図に置き換えるか、どの2枚を1枚に統合するか**を
storyboard の `visual` 列に戻って決める。図の方式の選び方は `references/figures.md`。

## 余白

- 外周 padding は 48px 以上 (テンプレートは左右80px / 上56px / 下48px)
- 安全余白 48px の内側に本文を収める。プロジェクタの端切れとブラウザのUI被りに効く
- **どの要素も 0–1600 / 0–900 の外へ出ない。** 出たら block。
  `overflow:hidden` で隠れているだけの状態は、PDF出力や別環境で表に出る

### 余白の意味構造（実験的計測）

`html-deck-check` は、文字のインク量 (`text_area_ratio`) と別に、意味要素のunion矩形から
`metrics.space` を返す。背景・装飾は除外し、画像は表示矩形を占有とみなす。

- `occupied_ratio` / `whitespace_ratio`: 意味要素の面積と空白の面積
- `outer_margin_min_px`: 意味要素からキャンバス端までの最小距離
- `group_separation_ratio`: 群の外側距離 / 群の内側距離。1.5未満は review
- `largest_void_ratio`: 32×18セルで見た最大の空白連結領域
- `entry_candidate_count`: 面積・文字サイズ・コントラスト・孤立度・primary役割の代理スコア
- `gap_rhythm_cv`: 主要要素間隔の変動係数。初期実装では info のみ

必要なスライドだけ、`data-space-role`、`data-space-group`、`data-space-intent`、
`data-space-profile`を宣言する。`edge`、`hero`、`breath`、`full-bleed`は意図した空白や
端までの配置を示す。これは自動レイアウト指示ではなく、数値を人の判断に戻すための補助情報。
余白率・群化比・最大空白の数値は block にはせず、既存の可読性・はみ出し検査を優先する。

### 構図フレームの一所有者原則

上の `metrics.space` は「どれだけ占有したか」を見る。一方、DOMの構図が壊れているかは
`metrics.layout` で見る。構図フレームの内側幅を `A`、兄弟内容を `C_i`、親の分離スロットを
`G_i` とすると、横方向は次を満たす。

```text
A = Σ C_i + Σ G_i
```

`G` を親の `gap` と子の `margin` の両方で作らない。実際の間隔は
`親gap + 前の子の外側margin + 次の子の外側margin` なので、同じ隙間を12px以上ずつ二重に
所有したら `redundant_gap_owner` を block にする。

比較・表・大きな構図の中央はキャンバス中央から16px以内に置く。兄弟の実矩形の重なりは
交差面積64px²以上かつ小さい側の2%以上で `layout_overlap`。子群のunion中心が親の内側中心から
16pxを超えて片寄ると `layout_child_shift`。矢印・線・`connector`・`middle`は接続スロットであり、
軸方向96pxまたは親の内側幅の12%を超えると `connector_track_wide`。いずれも好みではなく、
親が空間を一度だけ配分しているかの検査なので block とする。

この検査の対象は、`data-space-frame` を付けた領域、表・比較クラス、または幅720px以上の大きな
grid/flex。小さなカード内部まで構図フレームとみなさない。詳細な式、中央配置、修復順序、
例外属性は `references/whitespace-theory.md` を正本とする。

## 色

- 本文と背景のコントラスト比 **4.5:1** 以上。大きい文字 (32px以上、または24px以上の太字) は **3.0:1** 以上
- 色を **4〜6色**に絞る。役割で名前を付ける (`--accent` であって `--blue` ではない)
- 強調色は1枚に1箇所。2箇所以上あるとどちらも強調でなくなる
- 色だけで区別しない。凡例・ラベル・形も併記する (色覚特性とモノクロ印刷)
- **theme.css のトークンにない色を各スライドで作らない。** 検査は `palette_drift` として
  全部拾う。1枚の都合で増やした色は、デッキ全体の声を割る

## 書体

外部フォントは読み込めない (CSP と オフライン配布)。選択肢は2つ。

1. ローカルにある face で組む。macOS なら Hiragino Kaku Gothic ProN / Hiragino Mincho /
   Yu Gothic / Helvetica Neue / Avenir Next / Optima / Georgia / Baskerville /
   Futura / SF Mono / Menlo あたり。**配布先にも同じ face があるとは限らない**ので、
   スタックの末尾に必ず `system-ui, sans-serif` を置く
2. woff2 を `deck/fonts/` に置き、`@font-face` で相対参照する。ライセンスを確認する

配布先の環境が固定できないなら、フォント差で崩れない**固定PDF**を納品形式にする。

## 安全性・配布

- 外部URL参照ゼロ (`src` / `href` / `url()`)。オフラインで開けない資料は配れない
- スライド内に `<script>` を置かない。ビューアは `sandbox` 付き iframe で読み込む
- 各スライドに CSP メタタグを残す
- `<title>` は主張を言い切る一文。ビューアの一覧とスクリーンリーダーがこれを読む
- `lang="ja"` を設定する

## 数値の外し方

上の値は「迷ったときの初期値」であって、守ること自体が目的ではない。
外す条件は1つだけ: **外した結果、伝わりやすくなったと説明できること。**
説明を deck.md の `accepted` に書けば、それは契約の一部になり、
以降のラウンドで批評担当が蒸し返さない。書かずに外したものは、ただの逸脱として直される。
